# MVP 产品需求

状态：M9-001 产品开发与交付已完成；M8-002 冻结 v1 评估结论 C 保留，v2 尚未独立评估，真实参与者测试明确延期。  
最后更新：2026-09-22

## 目标与范围

帮助日期和目的地部分灵活的旅客发现满足约束、可解释的多目的地旅行组合。当前产品定位为 **AI-assisted multi-objective travel decision prototype**；路线生成、约束和评分保持确定性。问题背景见 [问题简报](problem-brief.md)。

| 范围 | 首次验证 M1–M2 | MVP 目标 M3–M4 | M5 压力评估 |
| --- | --- | --- | --- |
| 地理 | 亚洲子集，约 8–10 个机场 | 约 20–30 个亚洲机场 | 40 个目的地、43 个亚太机场的模拟目录 |
| 出发 | PVG、HGH | PVG、HGH，NKG 可选扩展 | PVG、HGH、NKG |
| 行程 | 7–21 天；基准集另含小型边界案例 | 7–21 天 | 7–21 天 |
| 目的地 | 必去集合与 0–4 个可选目的地 | 同左 | 同左 |
| 数据 | 固定模拟数据 | 模拟数据加少量人工报价样本 | 仅确定性模拟数据 |
| 交互 | 结构化输入、文件结果与对比表 | 可分享的 Streamlit 表单、结果对比与 Pilot 记录下载 | 无新增 UI |
| 搜索 | 小规模精确基准 | 先测性能，再决定是否需要近似模式 | 测量原 exact DFS，不优化 |

机场数量不是目的地数量。0 个可选目的地是必要的比较基线。必去集合允许为空，但完整行程至少实际访问一个目的地；有多个必去地点时仍必须全部满足，不另设隐藏截断。

M9-001 在上述历史基础上交付可展示、可分享的产品：升级本地 Streamlit，并用同一核心提供 FastAPI 与静态 Web 的单应用演示，发布到 GitHub/Vercel。描述目录覆盖 40 个目的地；公开搜索采用 M6 固定子集的 18 个目的地、264 条模拟报价，日期集中为 2027-10-01 至 2027-10-22。没有扩大为真实库存或市场覆盖承诺。公开部署结果以 README 中已核验地址为准。

## 输入语义

- 出发与返程机场分别指定集合，允许 PVG 出发、HGH 返回。历史手动表单可默认复制出发集合；M9 v2 自然语言未说明返程机场时保持空值，必须由用户明确选择或确认示例中的返程集合。
- 日期窗口限定第一段起飞和最后一段落地，按 Asia/Shanghai 解释。第一版不计算家到国内机场时间，界面不可称为精确离家/到家时间。
- 总行程天数为参考时区下最后落地日期减首次起飞日期再加一，且在用户给定的 7–21 天子范围内。
- 必去和优选集合按目的地 ID 指定，不按机场中转记录判断到访。
- 预算为一名成人、CNY、含税机票总价；报价必须满足同一行李口径。地面接驳估算单列。
- 输入偏好标签权重、每个单程报价允许的最大中转次数；第一版不支持自行转机，若请求允许自行转机则明确拒绝并说明版本限制，不静默改写。
- 第一版返程为最后访问目的地的接入机场到允许的国内返程机场；没有回到国内的行程不算完整结果。
- M9 v2 草稿的必要机场、日期、天数和预算允许为空；没有年份不按演示年份填补，“左右”等不明确范围要显示为未解决内容。只有完成编辑和明确确认的完整 TripRequest 可以搜索。Web 演示的输入预算上限为 CNY 50,000，每张报价中转次数支持 0–2；这些是交互边界，不是路线评分规则。

字段与边界口径详见 [数据模型](../data-model.md)。

## 用户故事

- US-01：作为日期灵活的旅客，我希望输入时间窗口和时长范围，避免逐天搜索。
- US-02：作为有必去地点的旅客，我希望系统保留必要停留，并探索额外目的地。
- US-03：作为预算有限的旅客，我希望看到最便宜方案及其交通代价。
- US-04：作为在意舒适度的旅客，我希望比较少折腾与偏好匹配的方案。
- US-05：作为需要核对的人，我希望看到各段来源、费用和时间，而不只看到总分。
- US-06：作为没有找到方案的旅客，我希望知道是数据不足、输入不支持，还是数据内没有可行解。
- US-07：作为只有模糊出行意图的旅客，我希望从真实语境的起点比较几种没有预先指定的组合。
- US-08：作为需要作取舍的旅客，我希望直接看到各方案相对最低价、最少交通和基线地点的差异。
- US-09：作为不了解目的地的旅客，我希望看到少量类型、活动、季节和交通提示，并知道哪些信息参与了优化。
- US-10：作为只有模糊想法的旅客，我希望先用自然语言表达条件，再检查系统理解是否正确。
- US-11：作为探索型旅客，我希望看到多个有意义的替代组合，而不是一个无法质疑的答案。

## 功能需求与验收

| ID | 需求 | 验收依据 |
| --- | --- | --- |
| FR-01 | 校验输入和支持边界 | 非法日期、预算、集合冲突、未覆盖 ID、自行转机请求有明确错误 |
| FR-02 | 加载并校验版本化数据 | 区分模拟/人工来源，检查外键、时区、报价口径、覆盖说明 |
| FR-03 | 联合搜索地点、顺序、日期、停留与返程机场 | 精确模式在小型案例与独立穷举一致；保留只去必去地点的可行路线 |
| FR-04 | 强制满足旅行硬约束 | 每条结果可独立复核预算、时间、停留、必去集合和连接限制 |
| FR-05 | 计算费用、负担、体验与 Pareto 关系 | 分项可复算，权重有版本，非支配定义与算法一致 |
| FR-06 | 返回少量有区别的方案 | 优先 3–5 个，候选不足时返回实际数量；相同方案的推荐标签合并 |
| FR-07 | 解释与对比 | 展示目的地顺序、日期、夜数、航段、估计机票费、交通时间、飞行日数、推荐分和主要取舍 |
| FR-08 | 标识数据和搜索限制 | 输出数据/评分/搜索版本，最优性范围与状态；无解不放宽约束 |
| FR-09 | 可本地交互 | M3 的表单复用核心校验与计算，调整输入能重新运行并比较 |
| FR-10 | 支持最小 Pilot 反馈闭环 | 匿名会话记录场景、结果、展示方案、选择、计时和结构化反馈；产品遥测与主观反馈分开，不自动收集个人信息 |
| FR-11 | 提供真实决策场景库 | 至少覆盖毕业旅行、海岛潜水、长假探索和高品质放松；包含意图、硬约束和权重，不硬编码优化答案 |
| FR-12 | 支持相对比较和目的地理解 | 对比价格/时间差、新增目的地和主要取舍；展示信息与优化数据分区，描述字段不进入搜索或评分 |
| FR-13 | 可选自然语言条件提取 | M9 v2 返回可空的严格 JSON 草稿；字段、类型、日期与目录白名单经本地校验；显示缺失、假设与不确定项，用户补全并确认后转换为原 TripRequest；失败时手动模式可用 |
| FR-14 | 发现与手动双模式 | 发现模式突出多个 Pareto 替代和取舍，不声明唯一答案；手动模式保留全部结构化控制 |
| FR-15 | 可追踪的目的地与报价资料 | FlightProvider 按起终机场及当地日期查询，返回整数金额、来源和时间；DestinationProvider 返回40份描述、版本、更新时间和模拟置信标记；描述与优化参数分离 |
| FR-16 | 可分享的完整产品演示 | Web 与 Streamlit 提供输入→编辑确认→搜索→比较→解释；从干净环境可安装，密钥仅服务端配置；GitHub/Vercel 发布以实际访问和端到端结果验收 |

FR-07 的解释使用模板与真实数值差异。只能将相同约束和数据下的其他完整方案作为比较基准；若“只去必去地点”无可行方案，不声称相对于它省钱。

## 非目标

支付、认证、预订、全球覆盖、实时航班 API/抓取、价格预测、自动拼接自行转机、酒店/活动联合优化、签证规则引擎、LLM 路线或自由生成解释、生产级云运维体系、服务端反馈数据库、多人票价、汇率换算。M9 公开 Web 演示和服务端模型 API 已在授权范围内；这不构成 OTA 或生产容量承诺。第一版不支持游览后从另一接入机场离开同一目的地；国内起终点不同的开口程仍支持。

输入“潜水”等偏好只用于标签排序，不生成活动日程或判定活动安全可行性，不将结果描述为可直接执行的详细潜水行程。

## 成功指标

以下门槛区分技术验证与真实用户验证。M2/M5 技术证据已有记录；理解、信任、有用性和规划效率仍未通过真实参与者实测。M9 产品交付另以 FR-13–16 的完整流程、干净环境、回归与实际部署验收，不用技术验收替代用户价值证明。

| 维度 | 指标与初步门槛 | 阶段 |
| --- | --- | --- |
| 正确性 | 基准案例返回结果硬约束通过率 100%；小型精确 Pareto 集与独立穷举一致 | M2 |
| 可复现性 | 相同输入及版本产生相同行程 ID 顺序、指标和搜索状态 | M2 |
| 性能 | 固定代表性任务集在记录配置的本机上 3 次中位耗时目标 ≤10 秒，同时报告样本、状态数及是否完整 | M5-001 |
| 近似质量 | 如引入近似搜索，在可精确求解集上报告各目标最优值差距、精确 Pareto 召回与耗时；接受阈值届时决策 | M3 |
| 理解 | 至少 80% 参与者能解释 T3 取舍、T4 数据边界及至少 3/4 推荐类别 | M4-001 |
| 信任与有用性 | 各至少 60% 达到评分门槛并提供行为理由；详见 Pilot 指标 | M4-001 |
| 用户发现价值 | 首批 5–8 名目标用户中，至少 60% 发现并愿意继续核对一个原本未想到的组合 | M4-001 |
| 规划努力 | 报告独立完成率、任务中位用时、提示和更快/更慢步骤；不作因果降幅结论 | M4-001 |
| 可核验性 | 人工样本中每条展示报价都有来源/采集时间/口径；记录复核差异而非保证可购买 | M4-002 |
| 规划效率 | 有同任务、同数据、交错顺序的配对基线后，才评估中位用时降幅目标 ≥30% | M4-002 |

小样本结果用于决定是否继续，不解释为统计证明。真实机票节省没有预设保证；必须在同源、同口径、同约束基线下计算。

## 跨文档一致性审查（2026-09-15）

方法：逐一对照范围、字段、公式、状态和引用；将 FR-01–12 映射到架构模块，检查算法状态是否能由数据模型表达，并检查相对文件链接。

| 检查项 | 结论与已统一的定义 |
| --- | --- |
| 术语 | 机场与目的地分离；单程报价与其航段分离；总行程天数、停留夜数、有效游玩分钟分别定义 |
