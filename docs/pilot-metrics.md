# Pilot 指标与记录规范

状态：Technical validation complete. User validation intentionally deferred. 指标已冻结，尚无真实参与者结果。  
最后更新：2026-09-17

## 记录机制

每次完成任务后，参与者在页面生成并下载一个 `pilot-record-v1` JSON。主持人把它与 [M4 结果模板](../pilot_results_template.json)中的观察字段合并。应用不自动上传、不写服务器数据库，也不收集姓名、邮箱、IP 或设备指纹。主持人另用 P01–P08 关联任务记录；分析结束 30 天内删除原始自由文本，仅保留去标识汇总。

### 产品遥测 `product_telemetry`

这些字段由应用产生，描述实际发生的产品行为：

| 字段 | 定义 |
| --- | --- |
| `session_id` | 浏览器会话生成的随机匿名 ID |
| `scenario_id` | 使用的固定场景或 `custom` |
| `result_status` | 优化器返回状态 |
| `feasible_result_produced` | 是否产生可展示的可行方案 |
| `recommended_alternative_count` | 页面展示的代表方案数量 |
| `recommended_alternatives_shown` | 排名、稳定行程 ID、类别、路线和模拟机票 |
| `task_completion_seconds` | 载入该场景到生成记录的单调计时秒数；刷新会重置 |
| 版本字段 | 数据、评分和搜索版本 |

### 主观反馈 `subjective_feedback`

这些字段是参与者判断，不能当作行为事实：

| 字段 | 定义 |
| --- | --- |
| `selected_itinerary_id` | 会优先继续核对的路线；无解时为空 |
| 三项 1–5 分 | 推荐类别理解、继续核对所需信任信息、下一步规划用途 |
| `discovered_non_obvious_route` | 是否出现原本没想到的组合：是/否/不确定 |
| `would_consider_selected_route` | 是否会认真考虑所选路线：是/否/不确定 |
| 两项自由文本 | 最难理解之处、真实决定前缺失的信息 |

## 五类核心指标

| 维度 | 计算与证据 | Pilot 通过信号 |
| --- | --- | --- |
| 理解 | T3 能说出一项收益和一项代价；T4 能区分样本内无解；测试后能解释至少 3/4 类别 | 至少 80% 参与者三项均通过，且无人把模拟价格当可购买价格 |
| 信任 | 信任评分 ≥4，且能指出至少一项仍需外部核对的信息 | 至少 60% 参与者满足两项 |
| 有用性 | 用途评分 ≥4，并能选出或明确拒绝一条继续核对的路线 | 至少 60% 参与者满足两项 |
| 非直觉发现 | T1 回答“是”，能描述原本未想到的组合，并愿意继续核对 | 至少 60% 参与者满足三项 |
| 规划努力 | 各任务独立完成率、计时中位数、提示次数；另记录参与者自述的日常耗时 | 至少 80% 核心任务独立完成，T1 与 T3 各自中位时间 ≤8 分钟 |

样本为 5 人时，60% 对应至少 3 人、80% 对应至少 4 人；8 人时分别对应至少 5 人和至少 7 人。中间人数按向上取整计算。结果只用于产品方向判断，不计算显著性或外推总体比例。

## 失败与决策规则

满足任一项即优先修正理解问题后再扩数据：

- 有参与者在任务结束后仍认为价格实时、可购买或覆盖现实全部航班。
- 超过 20% 的参与者不能解释 T3 的核心取舍或 T4 的样本边界。
- 超过 40% 的参与者无法在无主持人提示下选出或拒绝一条路线。
- 自由文本集中指出同一个术语或分数阻碍决策。

若理解通过，但信任、有用性或发现价值低于 60%，先检查信息层级和评分解释；不要因此修改优化算法。若发现价值与有用性均达到门槛，再进入人工真实报价样本验证。规划效率的“降低 30%”仍不能由本轮证明，因为没有同任务、同数据的配对人工基线。

## 汇总方法

1. 验证应用 JSON 的 `record_version` 和观察模板的 `schema_version`，按参与者和任务去重。
2. 将自动字段与主持人观察分别汇总，不用主观评分覆盖实际行为。
3. 报告参与者人数、完成记录数、缺失记录、每项分子/分母和中位时间。
4. 将原话按主题归类，保留反例；不只摘录支持产品的意见。
5. 对照上面的预设门槛形成“继续 / 先修正再测 / 停止”建议。
