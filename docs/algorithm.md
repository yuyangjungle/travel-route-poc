# 路线搜索与评分

状态：M2 完整搜索正确性保持不变；M5-001 已测量规模边界；M6/M7 只改输入与展示层，算法未变。  
最后更新：2026-09-17

## 1. 问题定义

在带日期和时刻的单程报价图上，寻找从允许出发机场到允许返程机场的完整旅行。中间访问至少一个目的地，全部必去目的地恰好访问一次，可选目的地数量为 0–4 且不超过请求上限。全部访问不重复；报价内部机场中转允许重复，但不产生目的地收益。

同时选择目的地子集、访问顺序、出发日期、停留夜数、单程报价和返程机场。单程报价可包含受保护联程，不在算法内组合其航段。

有限输入与单向推进的时间使搜索空间有限，但组合数量仍可能很大。精确最优性只针对加载的数据快照与下述离散停留规则，不针对真实全球票价。

## 2. 状态表示

搜索标签位于“已完成一段入境报价、尚未决定当前目的地何时离开”的节点：

| 字段 | 含义 |
| --- | --- |
| current_destination_id / access_id | 当前地点及本次固定进出机场 |
| destination_arrival_at | 入境落地加接驳后的可停留起点 |
| first_departure_at | 首段起飞，决定总行程天数 |
| visited_destination_ids | 包含当前地点的唯一访问集合 |
| remaining_required_ids / optional_count | 剩余必去集合与可选计数；M2 用 frozenset，不引入位掩码 |
| flight_total_minor | 已用报价费用，供预算硬约束检查 |
| offer_ids / access_ids | 不可变、有序报价和接入映射路径 |

对应 [ItineraryState](../travel_core/models.py)。M2 不做部分状态评分或支配剪枝，因此不存储暂时用不到的交通/体验累计值；在完整路线复核时从原始路径重算。飞行日统计仍使用日期集合，避免重复计数。扩展先验证当前 Visit，再建立下一目的地状态；返程只追加回国报价。

## 3. 搜索与停留枚举

1. 对请求窗口内所有可用首程报价，尝试其到达机场映射的可访问目的地。以所有适用目的地为候选，不仅是优选集合。
2. 到达当前目的地后，扫描所有从其接入机场出发的报价。每条报价隐含一个目的地离开日期和停留夜数，逐条检验。M2 不先枚举夜数或建立日期索引，避免提前优化；这与完整枚举可行夜数的离散模型等价。
3. 对每个报价计算 destination_departure_at = 起飞 − 返机场接驳 − airport_buffer_minutes。
4. 只保留本地日期差处于 min/max_stay_nights 范围、离开晚于抵达、可用分钟满足最低要求的选项。凌晨起飞必须先扣接驳和缓冲，再计算目的地离开日期。
5. 可选扩展为未访问目的地，或在必去已完成时尝试返程机场。中间访问不允许无报价的跨机场移动。
6. 对完整路线计算所有约束、指标，再进行 Pareto 筛选和展示选择。

第一版始终在同一 access 机场结束当前访问。多个目的地共享机场时，不允许仅靠零成本虚拟边依次“打卡”；当前模型需要实际报价连接。如果未来需要当地串游，必须新增明确的地面交通边及范围决策。

## 4. 硬约束

- 第一段起飞、最后一段落地位于请求窗口，参考时区固定 Asia/Shanghai。
- trip_days 在请求范围内，起终点分别来自指定机场集合。
- 每个 Visit 满足 min/max_stay_nights 和 min_usable_minutes，离开晚于到达。
- 所有 required_destination_ids 实际访问一次；可选数量不超上限；总访问数至少一。
- 单程报价首尾与访问机场相接，时间递增；报价内连接数不超请求值。
- self_transfer=false；多个航段的报价必须标为 protected_connection=true。
- 统一 fare_profile_id、CNY、单人，机票总价不超预算。
- 机场与目的地都有有效引用；没有报价时不能生成航班。

地面接驳费用单列，不加入 flight_budget_minor 判断。机场缓冲减少有效停留，交通总时长按数据模型口径不含该缓冲。

## 5. 精确搜索与安全剪枝

M2 当前使用固定顺序的深度优先完整枚举。只拒绝已违反日期、预算、中转、停留或访问数量等硬约束的扩展，不使用下界剪枝、支配剪枝、日期索引、束搜索或时间限制。完整路线再次进行独立于状态累计值的复核。

以下仅为未来可评估的安全剪枝规则，未在 M2 实现：

- 已超预算、最晚返回日、最大总天数或目的地数量上限。
- 已用时间加未完成必去地点 min_usable_minutes 的总和，即使用零交通时间的乐观估计也无法按期返回。不能把 min_stay_nights 直接乘 24 小时作为下界：跨午夜的一夜可能远短于 24 小时。
- 累计费用加可证明不高估的返程/必去费用下界仍超预算；不能证明安全时使用 0，下界不得把缺边当免费可行路线。
- 在后续选择相同的状态间做支配剪枝。

安全支配比较至少要求：相同 current_destination_id、access_id、destination_arrival_at、first_departure_at、visited_destination_ids、flight_dates。required_mask 和 optional_count 应一致。比较累计费用、负担组成、已结算收益；费用/负担均不高，收益不低且至少一项严格更好时才能丢弃被支配标签。

M2 没有状态支配剪枝。只比较“同机场、费用更低”会误删解；仅以到达更早也不能断言更好，因为日历夜数和每日有效时间会变化。未来加入剪枝须重新比较完整集合，并保持等价路径的语义。

## 6. 优化目标与显式评分

主要目标向量：**最小机票费用 C、最小交通负担 B、最大体验收益 E**。

### 偏好与体验

令目的地标签值 t 为 0–100，请求标签权重 w 为 0–100：

```text
match(d) = sum(w[tag] × t[d,tag]) / sum(w[tag])
若权重和为 0，则 match(d) = 50
若 d 在优选集合：match'(d) = min(100, match(d) + 10)
否则：match'(d) = match(d)

stay_factor(d) = min(1, stay_nights / recommended_stay_nights)
season_factor(d) = season_scores_by_month[访问开始的当地月份] / 100
visit_experience(d) = match'(d) × stay_factor(d) × season_factor(d)
E = sum(visit_experience(d))
```

最低有效分钟是硬约束。饱和收益避免靠同一地点无限延长停留刷分。首期不引入“同类体验重复惩罚”：其是否符合用户偏好尚未知，还会增加状态依赖。增加地点确实可能提高 E，但需要消耗天数并增加 B/C，由多目标取舍控制；M4 若发现堆站偏差再校准 A-03。

preference_match_points = E，首期“偏好匹配”和“体验收益”不是独立目标，也不输出两个伪装成不同的推荐。

### 交通负担

初始参数仅用于建立可解释基准，尚无行为研究支持：

```text
B = transit_minutes / 60
    + 2 × flight_day_count
    + 1.5 × connection_count
    + night_flight_minutes / 60
```

既保留原始指标，也显示 B 的分解。自行转机已禁止，不增加永远为零的自转机评分项。

### 综合推荐分

采用固定尺度，不依赖当前候选最大/最小值：

```text
cost_quality = 100 / (1 + C / 300000)     # C 为分，300000 分 = 3000 元
comfort_quality = 100 / (1 + B / 24)
experience_quality = 100 × E / (E + 100)
recommendation_score = 0.35 × cost_quality
                     + 0.30 × comfort_quality
                     + 0.35 × experience_quality
```

这些尺度使指标落在可比较范围，不能解释为满意概率。M1 将初始参数固定为 `score-v1`，见 [scoring.json](../data/m1/scoring.json)，参数有用性仍待验证。中间计算保留 40 位十进制精度；最终 B、E 和综合分采用 ROUND_HALF_UP 保留 6 位后参与完整候选比较；展示可再格式化到 1 位，不用展示精度决定支配关系。部分状态不根据舍入后的严格优势删除路径，以免丢失最终量化后等价的路线。

ScoringConfig 初始值还包括：airport_buffer_minutes=120、usable_day_start_local=08:00、usable_day_end_local=20:00、night_start_reference=00:00、night_end_reference=06:00、preferred_bonus_points=10。停留收益公式属于 scoring_version。时间和阈值是模拟规则，见 A-02/A-03。

## 7. Pareto 与结果选择

完整候选 a 支配 b 当且仅当 C(a)≤C(b)、B(a)≤B(b)、E(a)≥E(b)，且至少一项严格更优。先获得非支配集，再选展示结果；不能先仅按综合分筛掉候选再称其为完整 Pareto 集。

从非支配集中选择：最低 C、最低 B、最高 E、最高综合分。标签分别为最便宜、最少折腾、偏好最匹配、综合推荐。多个标签命中同一路线时合并，再按综合分补充目的地顺序不同的候选，目标 3–5 个，数量不足就返回实际数量。

精确路径先按报价和访问序列去重；展示补充优先不同目的地顺序，但不为多样性隐藏最低费用等极值代表。排序并列时依次按费用升序、负担升序、体验降序、报价 ID 序列字典序、access ID 序列字典序稳定排序；目的地由 access 唯一确定。

主要取舍从分项差值生成，例如相对当前综合推荐多花多少、少几个飞行日；比较双方必须具有相同请求与数据版本。没有可行基准则不生成节省声明。

## 8. 运行状态与近似模式

精确模式完成后，optimality_scope=`dataset_and_discrete_model`。无结果时为 no_feasible_in_dataset，附覆盖警告；不能声称现实中无航班。

未来如果需要 bounded 模式，优先固定 expanded_states 上限和稳定扩展顺序以便复现。截断后返回 search_incomplete、search_complete=false、optimality_scope=found_candidates_only；如有候选，只声明候选内非支配。近似搜索的保留规则另立 ADR 并测试，本文不预先规定束宽。

其他拒绝/数据状态与字段见 [数据模型](data-model.md)。无解解释先列观测到的失败原因和覆盖限制；除非额外执行反事实检查，不宣称某一个约束是唯一根因，也不自动修改请求。

## 9. 验证与未来改进

M1 校验器仍只复核手工见证和充分无解证据。M2 已另行运行真实搜索，不向搜索器传入这些答案。详见 [基准说明](benchmarks.md)。

M2 的独立 oracle 先枚举目的地排列、接入映射，再组合各航段报价，最后调用 M1 检查器。它不调用生产 DFS、约束或评分模块。20 个场景的完整可行集、指标和 Pareto 集均已匹配；加上顺序交换、多个日期、四个可选地点、六个必去地点等测试，共 58 项通过。见 [M2 结果](m2-results.md)。

M5 使用同一精确实现测得：small 71 个状态，medium 1,026 个状态，large 12,177 个状态；40 目的地 large 案例三次未插桩运行中位数约 7.0 秒。主要成本来自逐状态扫描全部报价、重复本地时间计算、完整候选留存和 O(R²) Pareto。详见 [性能报告](m5-performance-report.md)。

M6 未修改本章任何搜索、可行性、评分或 Pareto 规则。推荐说明和比较表只对代表方案的既有指标计算显示差值；描述性目的地信息不进入状态或目标函数。四个 M6 场景没有预置答案，仍由 exact-dfs-v1 计算。

M7 也未修改本章规则。LLM 输出只有在转换成合法的既有 TripRequest、经用户确认后才调用 `search()`；算法不知道请求来自自然语言还是手动表单。相同 TripRequest、数据和报价子集的输出保持一致。

后续优先顺序为：报价/日期索引与缓存 → 可证明安全的预算/日期/必去下界剪枝 → 严格状态键下的多目标标签或动态规划 → 明确标注的 beam search；CP-SAT 作为同基准对照。任何精确改动都必须保持 M2 oracle 和 M5 确定性摘要；近似模式必须报告质量损失与不完整状态。后续可评估活动级约束、重复体验收益和目的地异机场进出，但均需先更新产品范围、数据模型及 ADR。
