# M6 真实决策场景库

状态：M6-001 已实现。  
最后更新：2026-09-16

## 目的与边界

场景库把模糊旅行意图转成可重复的结构化输入，用于演示用户能否发现和比较未预先指定的多目的地组合。产品当前定位为 **AI-assisted multi-objective travel decision prototype**；路线、可行性、评分和 Pareto 筛选仍由确定性内核完成。本阶段没有 LLM 运行时、真实报价、预订或市场验证。

四个场景都使用 `data/m5` 的确定性模拟目录，以及 [固定报价集合](../scenarios/m6/offer_sets/m5-medium-v1.json)。价格、季节和描述信息全部是模拟数据，只能用于产品演示。

## 结构化格式

每个 `m6-scenario-v1` 文件包含：

- `traveler_profile`、`expected_user_intent` 和 `decision_priority`：说明用户决策语境，不参与优化计算。
- `must_have_constraints`：便于演示人员核对的约束摘要；权威计算输入仍是 `request`。
- `dataset_path` 和 `offer_set_path`：固定数据快照与报价子集。
- `request`：直接映射到 `TripRequest`，包括机场、窗口、时长、预算、必去/优选地点、偏好权重和连接限制。

场景文件不保存预期路线、预期分数或答案。搜索结果必须由当前确定性优化器从固定输入计算，避免把演示答案硬编码进产品层。

## 当前观察结果

在 2026-09-16 的 `data/m5-v1` 与 exact-dfs-v1 上，四个场景均能产生多个可比较方案；长假探索的候选空间明显大于其他场景。这些数字是回归运行的观察值，不是产品期望或场景验收答案，未来数据版本变化时可以改变。

## 目的地展示信息

[destination_descriptions.json](../data/m6/destination_descriptions.json) 只提供目的地类型、适合活动、季节说明和交通难度文案。界面将它与优化字段明确分区：

- **优化数据**：推荐停留夜数、月份季节系数、机场接驳分钟数；参与搜索或评分。
- **展示信息（模拟）**：目的地类型、活动、季节与交通说明；只帮助理解，不进入评分、约束或路线生成。

推荐停留时间来自优化目录，不在描述文件中维护第二份数值，避免两个来源漂移。所有季节说明都提示需要用真实天气与运营信息复核。

## 未决产品假设

- 用户是否认为系统发现的额外目的地具有启发性，而非随机复杂化。
- 价格、交通负担和体验匹配的相对解释是否足以支持初筛。
- 当前标签和模拟目的地说明是否能表达真实决策中的关键偏好。
- 用户是否理解“新增目的地更便宜”只是在同一模拟报价子集内的相对结果。

这些问题应通过 M6 演示后的用户任务验证，不能由场景数量或搜索通过率代替。
