# M2 确定性搜索：结果与限制

状态：已完成。  
最后更新：2026-09-16

## 本次交付

实现不可变行程状态、确定性完整 DFS、日期/预算/必去地点/停留/中转约束、独立评分、完整 Pareto 筛选和代表推荐。仅本地核心与文件 CLI，没有 UI、外部 API 或性能优化。

搜索入口是 [search](../travel_core/search.py)。只接受结构化 TripRequest、已加载 Dataset 和可选报价 ID 子集，不接受见证行程或预期答案。报价按起飞时刻、ID 排序，访问映射按目的地、ID 排序，输出按固定规则排序。

## 调用方式

~~~python
from pathlib import Path
from benchmark_tools.validation import load_dataset, read_json
from travel_core import search

project = Path(".")
data = load_dataset(project / "data/m1")
scenario = read_json(project / "benchmarks/scenarios/B01.json")
result = search(scenario["request"], data, scenario["offer_ids"])
~~~

不传第三个参数表示搜索所有加载报价；传空集合表示没有可用报价。返回：

- feasible_itineraries：全部可行路线，供正确性审计。
- pareto_itineraries：完整非支配集。
- itineraries：至多 5 个代表结果，合并最便宜、最少折腾、偏好最匹配和综合推荐标签。
- status、search_complete、optimality_scope：区分无解、输入错误和覆盖不足。
- allowed_offer_ids、data_fingerprint、各版本：记录比较范围。

~~~powershell
py -3.12 -m benchmark_tools.run_m2
py -3.12 -m benchmark_tools.run_m2 --scenario B01 --json
py -3.12 -m unittest discover -s tests -v
~~~

## 独立性与验证方法

1. 保留原 M1 数据、预期与内容锁。
2. 生产 DFS 自行发现完整路线，不参考手工见证。
3. 测试 oracle 独立枚举目的地排列、接入映射和报价组合；由 M1 evaluate_witness 计算有效性和指标。
4. 比较全部可行路径，而不只比较条数或最便宜路线。
5. 比较每条可行路径的全部 M1 指标，并用独立两两比较得到 oracle Pareto 集。
6. 验证手工有效见证被发现、无效见证不进入可行集。

oracle 不调用 travel_core 的搜索、约束、时间统计或评分实现；两者共享数据/请求校验和固定时区解析。因此这是独立算法实现对照，不是两套独立航班数据或规则来源。

### 具体发现

- B01：保留 ¥3,600 / 14 小时 / 2 个飞行日的基线，以及增加 KL 后 ¥2,800 / 18 小时 / 3 个飞行日的行程，二者互有取舍。
- B03：¥2,800 长中转路线仍可行，但负担分 52.5，高于基线 18；不能只按票价选唯一结果。
- B06：除手工列出的加 KL 行程，搜索自行找到该报价子集内的有效基线；停留过短路线被排除。
- B15：HGH 出发比 PVG 出发少 ¥200，负担/体验相同，因此后者被支配。
- B20：PHUKET 的费用、负担和美食体验均优于 SEMPORNA，Pareto 集只剩一个方案。

## 测试结果

已执行完整 unittest suite：58 项通过，其中 M1 30 项、M2 28 项。

新增覆盖包括：

- 在内存中加入原见证不存在的新报价，确认搜索发现新路线。
- 同一目的地组合的两种顺序、多天返程和不同停留夜数。
- 同一目的地有多个接入机场，但一次访问仍从同一机场进出。
- 1 个必去 + 4 个可选地点，以及 6 个必去地点，无隐藏总站数限制。
- 日期窗口、总天数上下界、最低有效分钟、最长停留、预算差 1 分、空报价子集。
- 偏好、季节、饱和收益和六位小数评分与 oracle 对照。
- 等指标不同路线不互相支配；重复路径去重；代表推荐保留目标极值。
- 输入不被修改；M1 内容锁不变。
- 不同输入容器顺序，以及不同进程 PYTHONHASHSEED 下，JSON 输出一致。

## 规格落实与假设变化

- 没有改变硬约束、票价口径、评分系数或产品范围。
- M2 通过扫描全部报价推导停留夜数，暂不建立日期索引；不影响离散可行集。
- 状态只保存扩展需要的信息；交通指标和体验在完整路线时重算。
- 输出耗时字段为 null；本轮不测性能，不将测试耗时当作规模性能承诺。
- 取舍是结构化差值，未做界面排版或 LLM 解释。

## 已知限制

1. **组合规模。** 完整 DFS 保留所有可行路线，Pareto 为 O(R²)；没有缓存、索引、下界剪枝、束搜索或时间限额。尚未验证目标规模的响应时间。
2. **最优性范围。** 仅对加载数据、实际报价子集和已声明规则完整；模拟数据与稀疏覆盖不能证明真实世界最优。
3. **评分价值。** score-v1 是显式但尚未经用户校准的模型；月份评分、接驳时间等仍为模拟假设。
4. **旅行模型。** 每个目的地访问一次，同机场进出；不自动拼接自行转机，不支持地面串游、酒店/活动、签证或多人价格。
5. **诊断。** 无解时记录观察到的拒绝原因，不声称找到唯一原因或最小放宽方案。
6. **验证独立性。** oracle 与生产核心共享输入规则和时区数据；手工基准和边界测试不能替代真实数据验证。
7. **运行环境。** 已实测 Windows/Python 3.12.1/tzdata 2024.2；其他环境未实测。完整 CLI 结果包含报价引用，用户需通过数据集查看原始航段。
