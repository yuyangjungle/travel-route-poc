# M7-001 AI Travel Decision Product Prototype

状态：已实现，尚未进行真实用户验证。  
最后更新：2026-09-17

## 产品目标

M7 将结构化优化演示改造成一个更接近真实决策过程的体验：用户可以先用自然语言描述模糊意图，检查系统提取的结构化条件，再让确定性优化器发现并比较多个方案。

核心职责保持不变：

```text
自然语言 → LLM 结构化提取 → 白名单与 TripRequest 校验
        → 用户确认 → 确定性搜索/评分/Pareto → 多方案解释
```

LLM 不生成路线、不读取报价、不判断可行性、不修改评分。没有 API 配置时，手动规划模式仍可完整使用。

## 两种产品模式

### 发现模式

适合目的地尚未完全确定的用户：

1. 输入出发地、月份、时长、预算、必去地点和偏好。
2. AI 只返回严格 JSON。
3. 服务端把地点限制在当前机场和目的地目录，并再次调用现有 `validate_request`。
4. 用户检查日期、预算、必去/想去地点、偏好、中转上限和 AI 假设。
5. 用户确认后才调用 `travel_core.search`。
6. 展示多个 Pareto 代表方案及其价格、交通、目的地和体验取舍。

发现模式不输出一个“AI 最佳路线”。页面明确说明每个方案突出不同目标。

### 手动规划模式

保留 M6 的完整结构化表单和固定场景。API 缺失、解析失败、目录外地点或用户不接受 AI 假设时，用户可直接切换到该模式。

## AI 输出契约

`travel_ui.natural_language.extraction_schema()` 根据当前 DatasetManifest 动态建立 JSON Schema：

- 出发与返程机场只能是 PVG、HGH、NKG 中当前目录实际存在的值。
- 必去与优选目的地只能来自当前目的地 ID 枚举。
- 偏好权重必须完整覆盖当前 manifest 声明的七个标签。
- 日期、时长、预算、可选地点数量和中转上限必须给出。
- `assumptions` 显示模型如何处理模糊月份等信息。
- `unresolved_mentions` 保存目录外地点；存在未解析项时界面阻止搜索。

结构化输出随后还要通过本地类型检查和既有 `validate_request`。只有验证后的对象才会转换为原有 TripRequest；优化器接口没有新增字段。

## 数据与隐私边界

- 提示中只包含机场/目的地目录、偏好标签和数据覆盖日期，不包含 FlightOffer、价格或已知路线。
- OpenAI Responses 请求设置 `store=False`，不使用工具或会话状态。
- 用户文本会发送给配置的模型供应商；界面和部署说明要求不要输入姓名、证件或联系方式。
- API 错误只显示安全的回退消息，不向页面返回密钥或底层异常。
- M5/M6 的价格和目的地描述仍为模拟数据。

## 解释层

解释继续由确定性模板生成，使用已选代表方案的可复算指标：

- 当前模拟报价中的价格优势或溢价；
- 相对基线新增或移除的目的地；
- 交通时间、飞行日和中转代价；
- 与高权重偏好的匹配；
- 体验收益与便利性的主要取舍。

相对差值只比较同一请求、同一数据快照下实际展示的方案。描述信息不参与评分。

## 失败处理

| 情况 | 行为 |
| --- | --- |
| 未配置 API key | 禁用 AI 提取按钮，提示使用手动模式 |
| 输入过短或过长 | 本地拒绝，不调用模型 |
| API/SDK 失败 | 显示“AI 条件提取暂时不可用”，保留手动模式 |
| 非 JSON、字段缺失、未知字段 | 拒绝整个输出 |
| 未知机场/目的地、非法日期或预算 | 拒绝或放入未解析列表，不传入搜索器 |
| 目录外地点 | 显示具体未解析内容，并禁用确认搜索按钮 |
| 优化器无解 | 使用原有数据内无解说明，不自动放宽条件 |

## 验证边界

M7 新增测试覆盖：严格 schema、有效提取、目录外值、字段重叠、非法类型、非 JSON、短输入、API 适配参数、同一 TripRequest 的确定性搜索，以及无 API 时的手动回退。

这些测试证明软件边界和确定性保持正确，不证明模型在开放表达上的提取准确率，也不构成产品市场验证。
